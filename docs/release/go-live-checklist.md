# ClearedIn go-live checklist

Reviewed November 21, 2026 against commit `5281e65`. The website demo is public today. A working desktop Chrome and Firefox extension is a separate milestone. The [release ledger](gates.json) has 11 pending decisions for the full release.

## Path A — Announce the website demo

Visitors can try 12 category rules on 14 synthetic posts without an account, API key, or browser install. All eight public pages returned HTTP 200, allowed indexing, and had self-referencing canonicals. A missing page returned HTTP 404 with `noindex`. The live host serves HTTPS, CSP, HSTS, and cached fingerprinted assets. [Public demo](https://clearedin.sush.dev/demo/)

## Path B — Ship a working extension to both stores

Both MV3 development archives build successfully and pass the repository's artifact checks. All five installed settings smoke checks passed in each browser, including save, reopen and reset. Firefox used a temporary installation. The earlier baseline shipped an empty content entry point. The development update wires opt-in home-feed filtering with a browser-session key and fixed provider endpoint. The Firefox manifest uses a development ID and declares optional authentication and website content. [Content entry point](../../apps/extension/entrypoints/content.ts) · [Background broker](../../apps/extension/src/background/broker.ts) · [Provider registry](../../packages/providers/src/registry.ts) · [Manifest](../../apps/extension/wxt.config.ts)

LinkedIn explicitly prohibits extensions that change its site's appearance, including obscuring ads. Local processing still changes the page if it hides posts. The product owner confirmed authorization to build the opt-in home-feed workflow with the installing user's own key. The implementation excludes recognized sponsored posts. Confirm the scope of public distribution before submission. Store approval and LinkedIn authorization are separate decisions. [LinkedIn policy](https://www.linkedin.com/help/linkedin/answer/a1341387) · [User Agreement §8.2](https://www.linkedin.com/legal/user-agreement)

### I can do

1. [ ] **Qualify the implemented workflow.** Test onboarding, filtering, protection, reveal, pause, reset and restoration on the intended live feed. Record markup compatibility and actual model behavior for each provider offered at release. [Architecture](../software-architecture.md)
2. [ ] **Verify security and privacy.** Minimize transmitted fields and host permissions. Test opt-in, revocation, credential isolation, worker and browser restart, cross-tab limits, request cancellation and clearing local data. Inspect actual network traffic before, during and after processing. Review dependencies, packaged code and diagnostics for sensitive data. The checkout's full dependency audit reported one moderate development-tool advisory in `minimatch`. The production-only audit reported zero known advisories. Update or document the tooling exposure and rerun both audits. [Security design](../security-and-privacy.md) · [Advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249)

[Quality criteria](../testing-and-evaluation.md) · [Performance protocol](../../tests/performance/README.md)
